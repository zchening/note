### 更新内容

- 官网首屏可嵌入本服务
- 演示桥只在 /demo 挂载
- 修行首时间串没下划线
- 纯网页热更，无需新 APK

官网 ns.xuyinji.com.cn 的首屏不是截图，是同源 iframe 里的真 App，父页每 400ms 驱动它（自动填口令、判正文揭纱、每次刷新回到《晚风记》）。此前那个 iframe 指向老项目（8080 内联单文件），本次换成 NoteSyncX（8090），途中撞到两道硬墙，一并解决：

① CSP 的 `frame-ancestors 'none'` 会把同源 iframe 直接挡死（浏览器按文档 URL 算 origin，反代后就是 ns 域）。现改为 `'self' https://ns.xuyinji.com.cn`——只放行我们自己的官网，第三方仍嵌不了。

② bj 的编辑器由 Lexical 托管，官网老办法「直改 `#editor` 的 innerHTML + 调全局 addReminder」在 bj 上会把改动冲掉（模型没变，下一帧还原，且不落库）。新增 `window.__NOTESYNC_DEMO__`：整篇替换走真源 + 重放树 + 触发同步，加提醒走 reconcile 的正式通道（写 reminders → 对账铺标记 → 重放树）。**只在 `/demo` 这一篇挂**，其余笔记恒 undefined。

另修一条被官网照出来的既有 bug：正文里**行首**的相对时间串（"…\n周六 10:00 去书店"）永远铺不上下划线。真因在 `WD_SEG`——`(这|下)?\s?` 里的 `\s?` 在"这/下"缺席时仍然吃空白，于是匹配起点落在**上一行的换行符**上；reconcile 的 markAll 要求"整串落在本块内"（挡跨块匹配），这条前导换行让整串被挡掉 ⇒ 提醒在真源里活着、编辑器和官网上却没下划线。修法：把 `\s?` 收进 `(这|下)` 组内（`(?:(这|下)\s?)?`），没有前缀词就不再吃空白；分支 B 的裸时刻字符类同时排除 `\n`。判据：time-parse / reconcile / rem-rel-row 三套 72 条全绿，另加"这周三 / 下周五 / 周三 / 11月14日 / 明天下午三点"五种形态逐一核对。
