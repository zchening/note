用户三报，三处根修。

其一，豆包语音「说到一半被截断、继续说录不进去」。v3.1.4 真机日志钉死
漏拦形状：第一跳 129→21 被 extreme 拦下并冻结峰值后，第二跳 21→9 帧间
只掉 12 字（低于 absDrop 30）且 prevLen=21（低于 minPrev 40），v3.1.3 的
composing-mismatch 分支被两个幅度早退闷死，残串落账、组字帧全程空转，
屏幕钉死 9 字。修复：mismatch 指纹（组字串远长于文档且树真在掉）提到
一切幅度阈值之前判定；「树纹丝不动＋串远长于树」的空转形状仍留给空转
检测 reboot，两个机制按形状分工、互不踩踏（双向变异互验：mismatch 后置
⇒ COMPOSE-E2E-05 红；删掉 drop 条件 ⇒ WD-E2E-05/06/07 红）。顺修补解冻
锚蚀低：渐进放血后再大幅塌方时，解冻锚改取水位线会话峰值，不再用被放血
的模型长（COMPOSE-E2E-06 钉住）。

其二，诊断信息「复制成 txt」点击没反应。反馈条一直写在编辑器上传条
#uploadNote 上，而诊断面板在非编辑器态（?diag 直开、关于页连点标题）
照样能开——用户真机日志 inEditor=no，#uploadNote 不存在，每一级反馈
都被 if(!el) return 咽掉。修复：反馈条收进弹窗自身 DOM；导出链改五级
——App 原生分享面板（先写文件再直接拉 ACTION_SEND，一键发微信/QQ/文件
管理器，对应用户原话「点击后直接把诊断信息.txt分享到微信」）→ 原生落盘
Download/NoteSync → 网页 navigator.share → 桌面 Blob 下载 → 兜底复制，
每级都有明确提示，复制失败也不再静默。

其三，网页首页与笔记页排版全乱。根因不是缓存错配（v3.1.4 note 误判，
特此纠正）：Caddy bj 块的 CSP 还是 S7-b 时代的值，style-src 只有
'unsafe-inline' 没有 'self'——v3.1.x 起 CSS 外链成 app.css，而多个 CSP
头按交集生效，这份过期头把外链样式整页挡死（还顺带挡了 PBKDF2 的 Blob
Worker）。修复：Caddy 层删除 CSP，唯一权威回归 Node 服务端 P1-12；真
浏览器实测样式恢复、零 CSP 违规，老项目 9 个域名零回归。
