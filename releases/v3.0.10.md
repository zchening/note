### 更新内容

- 跨段合成塌方守卫
- 单帧灾难性丢字回退
- 豆包整理不再丢字

v3.0.9 的飞行记录器终于钉死真凶：**丢字发生在单个 insertCompositionText
事件内部、全程零 tree:\* / gate:\***。根因不是前四层修的「程序化动树」，
而是 **Lexical 原生合成回灌本身**：它的 composition 模型基于单个 TextNode
（composition key = anchor 节点），`$updateSelectedTextFromDOM` 只读 anchor
那一个 DOM 节点的文本写回那一个节点。豆包「智能整理 / 精炼润色」把整篇正文
作为一个组字串替换、跨多个段落，浏览器把正文收进 anchor、其余段落 DOM 被
移除时，Lexical 只回灌 anchor 那 19 字，其余 97 字随模型 reconcile 被吞
—— 单条 update 内 116→19。

修复（见 `sync/compose-guard.ts`）：在 update 监听里检测「合成进行中 + 单帧
灾难性塌方」（绝对丢字 ≥30 且相对丢字 ≥50%，跨段合成或极端塌方），命中即
把真源回退到塌方前那帧并重建树，避免损坏状态写回真源 / 推到远端。判定双保险：
只有在 compositionstart 时选区跨多个顶层块（豆包整理 = 全选替换）或单帧丢掉
>70% 且原文很长时才触发，正常打字每帧只是几个字的增删，两类都碰不到。

判据：`test/compose-guard.test.mjs`（COMPOSE-01~08，纯函数 + 状态机）+ e2e
`26-compose-collapse.test.js`（真实 compositionstart 事件 + 真实 ed.update 塌方，
戳进同一个 update 监听验证守卫把真源从损坏态救回，飞行日志留 gate:collapse /
cmp:start）。单测 928/928、e2e 273/273、typecheck 干净。
