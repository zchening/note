### 更新内容

- 修复语音输入时文字被吞错位
- 组字后延长冷却覆盖语音停顿
- 接入 Lexical 组字态兜底

语音输入（如豆包）在句子/短语之间有 1~数秒自然停顿，且实时转写过程中持续派发组字事件。
此前门控只在「组字中」或「键盘 1.5 秒活跃期」内拦回灌，语音停顿 / 连续转写时门控提前打开，
下一轮轮询 / SSE 的整篇重建（`docToLexical` 的 `root.clear()` + 重建）落在输入过程中，
把光标重置、把未提交组字串冲掉 ⇒ 字符丢失 / 错位（用户报障：一边说话一边转文字时被吞字、乱跑）。

修复（`packages/client/src/sync/ime-gate.ts`）：

1. 组字真实 `compositionend` 后额外再关 4 秒（`COMPOSE_COOLDOWN_MS`），覆盖语音句间停顿；
2. `onInput` 读 `Event.isComposing`：`input(isComposing=true)`（豆包每转一小段都派）⇒ 续冷却，
   语音「还在转」的整段过程门控都关死；键盘 `input(isComposing=false)` 不延长（仍 1.5 秒，语义不变）；
3. 接入 Lexical `isComposing()` 作为防御纵深（只增不减），兜住 DOM 事件可能漏掉的组字窗口。
   `main.ts` 改为 `createImeGate(undefined, () => editor?.isComposing() ?? false)`。

判据：新增 `test/sync-ime-voice.test.mjs`（VOICE-01~06），已做双向验证（恢复态绿 + 变异态红）。
全量单测通过、typecheck 干净。

注：本发版仅含语音输入修复，阶段1 止血等其它改动未并入。
