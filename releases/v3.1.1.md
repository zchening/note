### 更新内容

- 离线草稿接入主流程兜底
- IME 组字提交后数字梗补扫
- 关于页改称关于 NoteSyncX

本版把 v3.1.0 已入库但零调用的离线草稿模块（sync/draft.ts）正式接进
主流程，并修掉三处接线期实测缺陷。

离线草稿（正文底线）：断推/被杀/断网时未推送内容先落本地加密草稿；
重开时草稿与开篇内容不一致弹「保留本机 / 使用云端」裁决条——保留本机
回灌草稿全文、推送恢复后自动清掉；使用云端丢弃草稿正文留在云端版。
推送成功清草稿挂在新回调 onPushed（云端无条件确认），不挂 onArchive
——后者带"被覆盖旧版非空且不同"双闸，首推不调，挂那里首推后草稿
永远残留（e2e 实锤）。两处接线期缺陷同步修掉：① 开篇裁决闸——装载
回声帧（before 还是旧值、canonical 恒"真变"）会把刚解出来的云端内容
当用户编辑写进草稿、顶掉真离线稿，restore 裁决完成前一律不记；
② 裁决基准修正——缓存缺失时 unlockIfRemembered 只能回 emptyDoc，
拿它当"云端"会把推送成功后的重开误判成冲突（e2e 实锤），现在缓存
缺失时在线拉一次真云端做基准，离线/解不开维持原判保守交用户裁决。

数字梗动画：安卓键盘 / 拼音 IME 的组字提交帧被组字闸挡掉且提交后无人
再扫，敲 520/1314/666 不放动画、回车+退格才放（用户报障原话）。
compositionend 后延迟一拍补扫，与 word-trigger 的组字上屏通道同款；
去重交给既有闩锁，重复扫描自动 no-op。notesync 烟花不受影响（它有
自己的 compositionend 通道）。

其他：关于页与菜单入口改称「关于 NoteSyncX」（用户拍板，与 APK 壳
应用名同口径）；MCP stdio 服务端（8 个工具）接入本机 mcp.json 为
notesync-bj 条目；e2e harness 的 addInitScript 从"只登记不消费"接成
真实生效（每页导航前执行）。

判据：全仓单测全绿（schema 75 / client 1012 / server 68 / mcp 27），
新增 WIRE/RESCAN/DRAFT-E1~3/EGG-E16 均经变异验证（拆实现必须红），
typecheck 三配置全绿。
